# 隐私与数据说明

## 数据来源

算力环读取以下数据：

1. 通过本机 Codex `app-server` 获取账户额度桶。
2. 从 `~/.codex/sessions` 和 `~/.codex/archived_sessions` 解析当天项目 Token 统计。
3. 通过 HTTPS GET 读取 `codex-resets.com` 的公开预警、重置消息及明确预告；数据来源链接为 https://codex-resets.com/zh-CN。
4. 通过 HTTPS GET 读取 `https://codex-reset.com/api/forecast` 的公开 24 小时展示概率；来源链接为 https://codex-reset.com/zh/。两站都有有效同窗口数值时在本机取等权平均；不上传本地数据，接口无需会员或 Key。
5. 「总览」页的五个额外账户（可选，读取失败不影响其他功能）：
   - DeepSeek：本机已有 API Key 调用官方 `https://api.deepseek.com/user/balance`，只读余额。
   - 豆包：经用户授权后，用 macOS 钥匙串中豆包客户端的解密密钥，在本机内存中解密该客户端自己的登录 Cookie，再调用 `https://www.doubao.com` 的会员额度接口；读取的是客户端当前 active profile（切换账号后可能是 Default / Profile 2 等其他目录），Cookie 仅在内存中用于向豆包官方接口认证，不写入额外文件、不发送给其他服务；手动配置 Cookie 的情况见本地存储说明。
   - WorkBuddy：通过 WorkBuddy 客户端自己的本机 IPC 通道（Unix socket，`~/.workbuddy/wbipc/endpoint.json`）读取其订阅积分；应用不读取、不保存 WorkBuddy 的 token，网络请求由客户端自身发出。
   - WorkBuddy AI（国际版）：与国内版使用同一套 IPC 协议，只把通道配置目录换成 `~/.workbuddy-ai/wbipc/endpoint.json`；同样不读取、不保存 token。
   - 千问办公：连接千问办公客户端自己的本机 MCP 通道（Unix socket，`/tmp/qwenworkcn-mcp.sock`），调用客户端注册的 `qwenwork.usage` 只读能力获取 Credits 用量，并读取 `qwenwork.settings.profile` 的套餐名与账户标识用于今日观测去重；应用不读取、解密或保存其登录 token，网络请求由客户端自身发出。
   - 百度搭子：读取 `~/Library/Application Support/qianfan-desktop-app` 下客户端自己的登录数据（`auth.json` 的 `cookies` 字段为 base64，布局 `iv(12) + tag(16) + 密文`，密钥是同目录 32 字节的 `.cookie-key`），在本机内存中完成 AES-256-GCM 解密后调用 `https://console.bce.baidu.com` 的积分接口；Cookie 只在内存中用于向百度官方接口认证，不写入额外文件、不发送给其他服务。与豆包一致，只用登录态的哈希指纹作为「同一账户」判据，用于今日用量去重，该指纹同样只保存在本机。

## 价格数据

「省钱灯」的模型价格、峰谷时段、节假日表和各渠道折扣是应用内置的静态数据（核对日期 2026-10-23），运行时不请求 DeepSeek、火山方舟、阿里云百炼或 WorkBuddy 的价格页面，也不上报用户的查询或阅读行为。页面里的来源链接需要用户点击后才会在浏览器打开。阈值、价目表和节假日表随应用版本更新；超过 30 天未核对时页面会提示「价格待核对」。

## 项目实际使用的数据

本地会话解析只保留：

- 会话 ID；
- 项目工作目录与末级目录名；
- 输入、输出、推理和缓存 Token 数量；
- 最后活动时间。

解析过程会在内存中读取 JSONL 文件，但不会把对话正文保存到本项目、写入额外数据库或发送给维护者。

## 网络与遥测

- 雷达请求不附带账号、令牌、额度、项目路径或会话内容；不保存第三方 Cookie 或凭据。第三方服务会收到正常 HTTP 请求元数据（例如 IP、应用 User-Agent）。
- 仅在应用运行期间每 15 分钟更新公开雷达，手动刷新最短间隔 60 秒；退出时取消网络任务。雷达快照仅在运行内存中保留。
- 余额来源每 5 分钟刷新一次；只请求上述厂商接口与 WorkBuddy、千问办公的本机通道，不向第三方发送余额或账户数据。
- 百度搭子的 Cookie 解密与请求只在本机进程内完成：解密结果不落盘、不写入日志，请求只发往百度智能云控制台官方接口。
- 本项目不包含自行上传统计、崩溃报告、广告或用户跟踪代码。
- 账户额度请求由本机 Codex 可执行程序处理，仍受用户自己的 Codex 客户端、账号和网络设置约束。
- 项目维护者无法通过该应用远程读取用户的额度、会话或项目目录。

## 本地存储

- 可选配置文件 `~/.config/codex-energy-bar/sources.json`（目录 0700、文件 0600）以本地明文保存用户显式填写的 DeepSeek Key 或豆包 Cookie 等凭证；不写入仓库，仅发往对应官方认证接口。未配置时应用会尝试使用本机已有的 DeepSeek Key。
- 读取豆包登录态需要 macOS 钥匙串授权（条目 `DoubaoWork Browser Safe Storage`）；授权弹窗由系统控制，拒绝后该账户显示「未授权」，可随时重试。解密得到的 Cookie 仅在内存中使用，请求结束即丢弃。
- WorkBuddy 的 IPC 凭据（ticket）只在读取时短暂使用，不记录、不落盘。
- 千问办公的 MCP 查询不携带额外凭证：socket 权限由系统账户控制，应用只发送查询请求，客户端自行附带登录态；返回的邮箱只在本机做带域分隔的哈希指纹，用于区分今日采样来源，不写入日志或账本明文。
- 应用通过 `UserDefaults` 保存窗口位置、界面大小、所选账户、自动隐藏设置、Mini 条是否显示省钱灯及今日观测账本。账本含采样时间、数值、币种和不可逆来源指纹，不含密钥或 Cookie；旧版账本保留作兼容数据。启动时丢弃旧采样基线，避免追补离线消耗。项目日志的增量解析进度只保存在运行内存中；退出或卸载应用不会删除或改写用户原有的 Codex 会话文件。

## 报告安全问题

请不要在公开 Issue 中粘贴完整会话日志、访问令牌、账号信息或包含隐私的绝对路径。安全问题请按 [SECURITY.md](../SECURITY.md) 中的方式报告。
